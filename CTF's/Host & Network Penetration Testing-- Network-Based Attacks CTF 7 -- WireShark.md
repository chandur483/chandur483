### **Explanation of Methods & Techniques Used**

The analyst used a combination of **Wireshark filters**, **packet inspection**, and **protocol analysis** to piece together the story of the infection.

1. **Protocol-Specific Filtering:** The primary method was using Wireshark's display filters to narrow down traffic to specific protocols (e.g., `http`, `nbns`). This is crucial for managing large packet captures and focusing on relevant data.
    
2. **HTTP Status Code Analysis:** Filtering for `http.response.code == 200` is a common technique to quickly find successful web requests, which often point to downloaded malware or attacker-controlled servers.
    
3. **Packet Detail Inspection:** For each filtered packet, the analyst drilled down into the protocol layers (Ethernet, IP, HTTP, NetBIOS) to extract specific information like IP/MAC addresses, URIs, and hostnames.
    
4. **String Search within Packets:** To find specific, hard-to-locate data (like a filename or a wallet ID), the analyst used the "Find" tool to search the raw packet bytes and packet details for key strings.
    
5. **Following TCP Streams:** This feature reassembles a session between two hosts, allowing the analyst to see the full conversation (request and response) in a readable format. This is invaluable for understanding data exfiltration or commands sent to a server.

### **CTF Challenge Notes & Answers**

#### **Q1: Initial Infection Point**

- **Question:** What is the URL accessed by the infected user that returned a 200 OK response code?
    
- **Method:**
    
    1. Applied the filter: `http.response.code == 200`
        
    2. Inspected the HTTP packet to find the `Request URI` field.
        
- **Answer:** `623start.site`
    
- **Why:** This URL is the likely source of the initial infection or a command-and-control (C2) server that the malware contacted, as it was successfully accessed (`200 OK`).
    

#### **Q2: Identifying the Victim Machine**

- **Question:** What is the IP address and MAC address of the infected Windows client?
    
- **Method:**
    
    1. Applied the filter: `http` to see all web traffic.
        
    2. Identified a packet with a "Windows Defender" reference, confirming it's from a Windows machine.
        
    3. Noted the **Source IP Address** from the Internet Protocol version 4 section.
        
    4. Noted the **Source MAC Address** from the Ethernet II section.
        
- **Answer:** `10.7.10.47, 80:86:5b:ab:1e:c4`
    
- **Why:** This uniquely identifies the compromised machine on the network.
    

#### **Q3: Discovering the Hostname**

- **Question:** Which Wireshark filter can you use to determine the victim’s hostname from NetBIOS Name Service traffic, and what is the detected hostname?
    
- **Method:**
    
    1. Applied the filter: `nbns` to show NetBIOS Name Service packets, which computers use to register and resolve hostnames on a local network.
        
    2. Expanded the `NETBIOS Name Service` section and looked at the `Queries` for the name being advertised.
        
- **Answer:** **Filter:** `nbns`, **Hostname:** `DESKTOP-9PEA63H`
    
- **Why:** NetBIOS is a legacy but still used protocol in Windows networks for host discovery. The hostname query reveals the computer's name.
    

#### **Q4: Finding the Compromised User**

- **Question:** Which user got infected and ran the `mystery_file.ps1` PowerShell script?
    
- **Method:**
    
    1. Used the "Find" tool (`Ctrl+F`).
        
    2. Searched for the string `mystery_file.ps1` within the **Packet bytes**.
        
    3. Once found, right-clicked the packet and selected **Follow -> TCP Stream** to see the full content of the transmission.
        
    4. The script content was visible in the stream, revealing the username.
        
- **Answer:** `rwalters`
    
- **Why:** The PowerShell script itself contained a reference to the user's directory or profile, identifying the account that executed it.
    

#### **Q5: Identifying PowerShell Traffic**

- **Question:** What User-Agent string indicates the traffic generated by a PowerShell script?
    
- **Method:**
    
    1. Used the "Find" tool (`Ctrl+F`).
        
    2. Searched for the string `PowerShell` within the **Packet details**.
        
    3. Located an HTTP request and expanded the `Hypertext Transfer Protocol` section to find the `User-Agent` header.
        
- **Answer:** `WindowsPowerShell`
    
- **Why:** The User-Agent is a header that HTTP clients send to identify themselves. The default for PowerShell scripts is "WindowsPowerShell", which is a strong indicator of automated script traffic versus a browser.
    

#### **Q6: Wallet Extension Theft**

- **Question:** Which wallet extension ID is associated with the Coinbase wallet?
    
- **Method:**
    
    1. Used the "Find" tool (`Ctrl+F`).
        
    2. Searched for the string `Coinbase` within the **Packet bytes**.
        
    3. Right-clicked the relevant packet and selected **Follow -> TCP Stream**.
        
    4. The stream revealed data being sent to a server, including a unique browser extension ID associated with Coinbase.
        
- **Answer:** `hnfanknocfeofbddgcijnmhnfnkdnaad`
    
- **Why:** Information stealers often target browser extensions (like cryptocurrency wallets) to extract sensitive data. The unique extension ID was part of the data being exfiltrated.

### **Summary & Key Takeaways**

- **Attack Chain:** The infection likely started when a user (`rwalters`) on `DESKTOP-9PEA63H` (`10.7.10.47`) visited a malicious URL (`623start.site`), which led to the execution of a PowerShell script (`mystery_file.ps1`).
    
- **Malware Function:** The malware acted as an information stealer, harvesting data from the compromised system, including credentials from the Coinbase wallet browser extension.
    
- **Core Wireshark Skills:**
    
    - **Filtering:** Essential for efficiency (`http`, `nbns`, `http.response.code`).
        
    - **Deep Inspection:** Always expand protocol sections to find key details.
        
    - **Searching:** Use "Find" in packet bytes for obscure data.
        
    - **Stream Reconstruction:** "Follow TCP Stream" is critical for understanding application-layer data exchange.
